Security & Privacy

Written for the people who get asked "is this safe to use in class?" — educators, IT reviewers, and data protection teams. The short version: The Slingshot is designed so that no personal data is processed, and every claim on this page can be verified by reading the open source code.

What the game is

The Slingshot is a single HTML file that runs entirely in the browser: no accounts, no logins, no cookies, and no personal data collected through gameplay. Game state exists only in the player's browser.

Trajectory benchmarking (optional)

  • Entirely opt-in — players can skip it and play the game unchanged, and Seed (learner) mode is never benchmarked.
  • Players are identified only by a self-chosen nickname and a study level — no real names, email addresses, accounts, or cookies.
  • Anonymous game outcomes (choices, milestones, valuation and similar gameplay metrics) are stored on EU servers (Frankfurt) solely to show players how their game compares with others.
  • The database is protected by row-level security: public clients can add and read benchmark entries but cannot delete records, and game outcomes cannot be modified once written.

Analytics

The game uses Umami, a privacy-focused analytics tool, to collect anonymous, aggregate usage statistics: page views, feature clicks, country-level region, and device type. Umami sets no cookies, builds no user profiles, and respects the browser's Do Not Track setting — which is why no cookie consent banner is required.

For university IT and data protection teams

  • No personal data collected. No names, emails, student numbers, or accounts anywhere in the system.
  • No cookies. Neither the game nor this website sets cookies or runs advertising trackers.
  • EU data residency. The anonymous benchmarking data that does exist is stored in Frankfurt, Germany. Nothing is transferred outside the EEA.
  • No integration with university systems. No LMS, no authentication, no licences to procure. Students open a web page.
  • Fully auditable. The complete source code, including every network call, is public on GitHub.
  • Offline option. Download the HTML file and run it locally, with benchmarking silently disabled.

In our assessment no DPIA is required, as no personal data is processed; institutions applying their own thresholds are welcome to contact us.

Security practices

The project repositories have GitHub's security features enabled, including private vulnerability reporting, secret scanning, and code scanning. The account is protected with two-factor authentication and the site is served over enforced HTTPS. All values returned from the benchmarking database are HTML-escaped before display.

Reporting a vulnerability

If you find a security issue, please report it responsibly to ammon.salter@wbs.ac.uk rather than opening a public issue. We will acknowledge receipt within 7 days and aim to address confirmed vulnerabilities promptly. The full security policy is published in the project repository.
